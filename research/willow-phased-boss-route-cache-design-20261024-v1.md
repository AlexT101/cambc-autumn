**Recommendation:** retain the existing logical singleton/admission state, but allow bounded reuse of its immutable static field storage. First separate altar reuse from exit changes; then, if useful, add one dormant home field. Do not cache forecasts, eligibility or selected geometry as part of this optimization.

## Exact keys and useful bound

`boss_transit_tile` (`136–146`) builds one per-actor immutable walls board from terrain, camp tiles and all static damaging-member ranges. Under that fixed board, a home field is a function of its **exit tile** (`285`), not current HP, enemy vision or camp sleep. Current position affects selection of station/exit (`boss_quote_geometry:548–567`) and lookup distance, so two groups do not imply only two possible home keys. A cache indexed solely by group would reuse an incorrect exit field. Use exact exit equality under the fixed map/board; retain group separately for policy state. With storage surviving a map/board change, include that identity or invalidate it.

A modest bound is two home fields total: one active and one dormant, keyed by exit. Deterministic replacement of the dormant entry affects only reuse, not nomination. Do not prebuild fields or allocate an entry per group/station/tile. Static per-field worst-spawn distance/failure can also be retained if computed identically, but is not necessary for the first change.

The altar field is a function of the same static walls and the allowed tribute-goal set (`294–305`). It does **not** depend on the boss group or exit. Keep one independent physical altar entry keyed by the existing ordered open/closed signature, recomputed from current enemy locks and the current avoid-altar deadline. Preserve the existing key arithmetic and goal construction for the smallest patch; changing key semantics is a separate concern. Query that field at each newly selected exit to obtain `p.bank`. Do not cache bank distance by group or reuse an old open-set result across lock/avoid changes.

## Preserve these control-flow details

1. The current logical switch condition is group differs, exit differs, or active home absent (`278`). It rejects a second switch in the same round and records `cold_round` **before** transit validation/construction (`279–285`). Apply this exact test before consulting physical storage. A physical hit must consume the same logical switch opportunity as a build would. Otherwise a cached alternative can be admitted where the parent returned false, altering candidate order and economy.

2. Preserve active validity, including failure paths. Parent switches group/exit and clears active home/altar before checking transit. A bad transit endpoint leaves no active home; an unreachable spawn leaves a built active home but no active altar. Physical cached objects may remain stored, but must not silently make those logical fields present. Quote selection (`646`) and returning-job admission (`841`) inspect active group/pointer presence before calling preparation. Either keep the active interface with dormant storage moved behind it, or introduce explicit logical validity flags and use them consistently at every existing check. Do not let an old physical altar satisfy the return-path precheck after a failed switch.

3. Continue evaluating all spawn distances with the same maximum, unreachable and256-step checks (`287–293`); compute `p.returns = back + p.corridor`. Do not replace this with current-spawn or shortest-spawn distance. Update the altar only at the same later point, then apply the same bank unreachable/256 checks and stale-world check (`294–310`). Cache hits remove work, not predicates.

4. Preserve `quote`, `forecast`, `quote_cursor`, `rejected`, active job/approach memory and the current warm-first/alternative nomination order (`590–659`). In particular, obtaining a physical field hit must not skip current pricing or make a retained quote eligible. Leave dynamic occupancy, enemy safety, fresh neighbor proof, local corridor validation, action/cooldown accounting and cycle ledger unchanged.

The smallest useful first patch can retain the altar object across logical switches behind an explicit active-valid flag, clearing that flag exactly when the parent resets it and reactivating it only upon reaching the existing altar stage. A two-entry home cache is optional additional reuse, not permission to enlarge the search. Both changes need source review of logical hits/misses/failures; runtime can then determine which cost path actually matters. Lower fuel can change rollover timing even with unchanged intended policy, so no replay-equivalence or strength claim follows from this design alone.
