`make_way` samples `occupancy_into(team::ally, allies)` at560, then performs guard/avoid tests and distance-field work before `cambc::vision::champion_at(a)`. The lookup and subsequent yield-priority reads have no local error handling. Fuel exhaustion can resume this computation next round after the sampled ally moved, disappeared from vision or died. The old occupancy bit is not a lifetime guarantee. A missing tile lookup then raises `api_not_found`98; a hidden entity/read can raise `api_not_in_vision`97. Today it escapes to the generic act error handler rather than the stale-turn path. The source has no explicit refresh or stale check between this occupancy read and the lookup. This establishes a feasible robustness failure, not its occurrence in the nominated game.

Smallest sound contract for a separate implementation:

1. Put a narrow `cambc::error` boundary around the existing ally lookup and its existing gem/type comparison reads only. Preserve their successful-path order, count and short-circuit tie behavior. Do not wrap route search, guard construction or movement in a broad catch.
2. Handle only `api_not_found` and `api_not_in_vision`; rethrow other codes unchanged. Use the exception's copied code, not its message text. Once the SDK has constructed the exception and captured the engine diagnostic, call `world_.throw_if_stale()` on this expected-failure path. Do not insert a round import between a failed raw call and SDK error construction: round queries clear the engine's last error.
3. If stale, let `StaleTurn` propagate to the existing turn runner. Never turn it into `false`, keep iterating an old occupancy board, or initiate a refreshed move from this stale invocation.
4. If still current, invalidate local Pathing occupancy/position caches and return `false` from the optional make-way operation. Do not guess which ally occupied the tile, assume its gem priority, mark the tile as a hidden move bump, or retry/rebuild the route here. The existing caller can retain its normal fallback behavior. The already-reached `route_exhausted_=false` need not be undone: failure to identify the ally is not proof that wider routing is impossible.

This adds no successful-path query, occupancy pass, visibility preflight, model work or fuel gate. A preflight `has_champion` would add cost and still race a later lookup under rollover. Exception structure can nevertheless change compiled code and fuel; source review does not certify runtime neutrality. This narrow fix also does not solve successful stale reads or every rollover race elsewhere. Do not expand scope to those without a separate contract.

Minimum future checks: identical success/priority-tie/accepted-yield behavior and import order; missing and hidden ally with unchanged round returns false without action and invalidates local caches; either expected error after rollover propagates `StaleTurn`; unexpected errors remain visible.
