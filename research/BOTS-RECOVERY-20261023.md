# Local bot-directory deletion and recovery

On 2026-10-23 at approximately22:12 UTC, a helper agent ran `rm -r bots` with the worktree root as its working directory while intending to remove an accidental nested directory. This deleted the checkout's tracked and ignored/untracked `bots/` trees. The follow-on source copy failed. The agent reported the mistake and stopped; root informed the user and paused development. No submission or remote deployment changed.

The affected checkout is `/Users/yufan/Desktop/Development/CambridgeBattlecode2026/willow-upstream-development`. Replay bundles, result tables, research, provenance, release ZIPs, maps and sibling checkouts are outside the deleted directory and survive. Before the incident, root's Git status showed no modified tracked bot files. HEAD was `87cbbfe`.

Root restored tracked `bots/` files from that HEAD. The canonical `bots/hyperion/src` aggregate was then independently recomputed as `337f42a54beb5890109e56b755237d8ea0d07abb240d095778f01e2098ab7b39`, exactly its frozen pre-incident value. An initial hash command mistakenly ran at the repository root and produced an empty-stream hash after a shell glob error; it was not accepted as verification. The subsequent command ran in the bot directory and verified the full source set.

A separate recovery agent is reconstructing untracked and ignored source trees from surviving Git commits, exact release ZIPs, source patches, per-file manifests and read-only sibling copies. All recovery writes use new destinations; existing files are not overwritten or deleted. Reconstruction is published to the former bot path only after matching its recorded aggregate. New directories are recovery artifacts, not the original directory metadata or build cache.

Khaos_v32 and Khaos_v33 sources have already been reconstructed from their respective preserved release archives and verified against their recorded per-file manifests and aggregates: `db5b37d5e5c609c2c616d3a39c0f1eb7f5adebf401dcd1be8848e0eede237ab8` and `a00fff454c1e48520968c9ba2d4c1ecdae0212ce019724dc06a6e959ddc3412e`. The tracked upstream v44 baseline independently contains the latter source.

The live inventory is `recovery/incident-20261023-bots-recovery/recovery-manifest.json`. It must distinguish verified source recovery, unresolved source copies, and deleted generated build artifacts. Existing runtime results retain their original pins; reconstructing sources does not retroactively claim that a newly built WASM is the old binary. Future builds must be checked against available original build hashes before being treated as the same frozen executable.

No new optimization source had been completed before the deletion, and the empty accidental `willow-comms-pair-index-work` directory is not a valid candidate.
