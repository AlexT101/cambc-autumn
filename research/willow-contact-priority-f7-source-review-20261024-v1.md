## Findings

- **Scheduling matches the design.** New and old allied ranks use the actual unchanged fallback versus13, count dead bodies, exclude self and break ties by handle. Enemy rank likewise includes every body but does not count itself. The slot formula matches `World::slot`, including parity and the larger team's tail. Both crossing inequalities are correct. A projected first enemy in an opponent-first round cannot qualify. Other actors may still change their priorities afterward; this remains a projection.
- **Freshness/readiness are appropriate for the narrow arm.** Candidates come from the existing alive/visible filtered native vector, then require `acted` plus current position, stats and priority rounds and no channel. `World::update_champion` computes ready rounds with `fire_round(round,cooldown,acted)`; an acted enemy receives the extra round, so `strike(e,r+1/r+2)` uses proper owner-turn cooldown timing rather than raw-zero cooldowns. It does not restore Willow's spent reset. The extra approach term is a geometric nomination across two future enemy activations, not immediate damage.
- **Lifetime and higher bands remain intact.** The saved pointer refers to the existing static live-enemy vector; intervening calls do not repopulate that vector. Endpoint storage is assigned together with the pointer and read only when it is nonnull. Existing kill/protect paths, fallback native reads, stale check and redundant write check retain their order. Context is only retained when no wish wins. The original spawn-membership query is now stored and reused: an initially duplicated bitboard host call was removed during review. No new fuel gate is introduced.
- **Camp guard is independent of priority ties.** It uses cached nearby groups and rejects potentially live damaging groups regardless of other champions' distance/order. Engine group-state code2 means cleared, code3 means respawning (`world.cpp:1637–1641`). A recent clear plus the full respawn interval gives a conservative earliest return; a known respawn must be strictly later than the next phase. Equality and stale clears reject. The guard does not confuse zero old-order camp damage, sleeping, stun or old member HP with safety after priority changes. Only the local index is queried; its cold miss still entails existing scratch-board host operations/storage costs.

## Final stun refinement verified

`strike` does not account for stun. Native `champion_info.state` has no named stun flag; used-up action flags on an acted enemy cannot substitute for buff duration. Final helper lines331–339 match the already-read `World::priority_start_enemies` record by handle and reject a missing or stunned record before the camp guard. This adds no native query or Enemy-vector layout change, and continues to another enemy after a rejected match. The snapshot uses `has_stun`, so it conservatively rejects duration0 stuns too; that coverage loss is explicit. It does not use the ally-only `ChampionBelief::stun_pending`. The public r161 Ryth export has no buffs, so this refinement does not itself reject that recorded geometry.

Exact public r161 activation remains unknown because Willow's private group7 clear/respawn belief is absent. This is not a prototype gate. Controlled states should check stun/missing-snapshot rejection, expired-stun conservative rejection, camp timing equality, live tied camps, the known-empty exemption and both team parities with unequal/dead rosters.
