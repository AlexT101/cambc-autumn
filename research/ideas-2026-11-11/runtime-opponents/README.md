# Runtime-configured synthetic opponents

User requested larger A/B batches, runtime opponent configuration instead of repeated compilation, and no metering overhead for the synthetic Fish/Mite opponents. Ocean candidate/reference and Ocean mirrors remain metered at the requested quantum. This changes the experimental opponent population; it does not retrospectively reinterpret old games or establish strength.

`tools/ab.py` and `tools/run_batched.py` accept `--experiment-config FILE`. The strict schema is `{"schema":1,"opponent_index":1,"maps":{"MAP_STEM":{"seed":1311004,"salt":1004,"unmetered":true}}}`. Every played map requires a configuration. Logical REF alone receives it, including after the A/B side swap. Results record the configuration-file SHA and each game's actual A/B mapping. The new programme binds REF to its sealed Fish/Mite replica sources; no configuration is supplied to Ocean mirrors.

The runner's manifest accepts `--runtime-config COMPACT_JSON`, with `a` and `b` entries, exactly one configured and the other null. Configuration belongs to a per-game cloned `Program`, then each draft/champion instance's private meter context. `env.experiment_config(uint32 key)` returns uint64 member seed for key0 and draft salt for key1. A runtime body missing configuration fails closed. Configuring a bot without this import fails closed, and ordinary Ocean cannot enter unmetered native compilation. Ambient per-bot fuel/unlimited/native-SO overrides are forbidden on configured manifests.

Native unmetered code has a distinct cache key (`unmetered-v1`), omits instruction/bulk-memory charges and fuel checks, skips host fuel charges, and reports `INT64_MAX` for fuel remaining. Opponent `.fuel` work values are zero because accounting is disabled; they do not measure a fuel saving. Existing teacher `FASTRUNNER_UNLIMITED_BOTS` behavior remains separate. Metered code generation remains unchanged. Seed/salt values are excluded from compilation/cache keys; internal PGO uses the fixed configuration1310001/1, independent of experiment seeds. PGO's existing unscored internal self-play remains; it is not part of the declared match sample.

Configured C++ builds reserve one shared slot each and use serial CMake. Then `--prepare-only` preloads the actual manifest's unique bot/metering entries under a full16-slot reservation (partial grants are released before retry). It returns before game dispatch. Cached batches then use ordinary shared-pool match slots. Ordinary nonconfigured preparation stays unchanged.

`--game-timeout SECONDS` is an opt-in **run-batch-only** watchdog, forwarded by both Python adapters. The parent starts the deadline on worker dispatch after precompilation, including worker startup. It kills and reaps only the owned timed-out worker, releases its slot, and retains a failed cell without retry. Even jobs1 uses this supervised worker path. The legacy native `--timeout` flag remains ignored; it must not be mistaken for this protection. The new protocol uses120 seconds. Preparation/build time is outside the per-game deadline.
