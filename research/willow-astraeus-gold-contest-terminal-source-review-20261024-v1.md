## Two pre-build requests

1. **Avoid per-group full-board allocations in qualification (`plan.cpp:867`).** `(G.tiles() & ~world.visible).is_empty()` allocates a complement and a separate intersection: SDK `bitboard::operator~` constructs storage; with `G.tiles()` as a const lvalue, `operator&` also constructs storage. Both subsequently free it. This is bounded by candidate groups, but it contradicts REVIEW.md's no-allocation claim and the intended cheap admission path. Use an existing reusable scratch operation or iterate the group's existing member positions for visibility; account for lazy `G.tiles()` construction if retaining it. Update the cost statement. This is a concrete fuel-contract issue, not evidence of a runtime fuel failure.
2. **Remove only duplicated goal credit (`plan.cpp:1879–1883`).** The current predicate zeroes the entire signed field-progress value for every eligible economic endpoint, including ordinary strike leaves, regardless of which group `intent.group` names. A gold endpoint k route steps farther from a distinct existing farm goal previously paid `-k * step`; it now pays zero. Actual movement still changes the subsequent route even though decide consumes the current turn's goal. Removing unused *later* walk credit is correct; removing unrelated signed route progress is not the same duplicate. Preserve the existing field term when it describes a different objective, and suppress only the same occupancy objective's duplicate credit, or explicitly redesign and justify this broader objective replacement before testing. Include away-from-goal and toward-goal controls. This request is about the intended isolation; source inspection cannot predict its win-rate effect.

## What is coherent in the inspected source

- The Prices cache retains the original complete key and refresh formula. `current_prices` only reads a matching prior quote; it cannot trigger `best_emblem`. It is not a freshly recalculated Upkeep quote: the baseline deliberately caches while upkeep changes. A changed share/stat/main/passive-family key or no earlier normal price calculation causes abstention. First-contact and repeated-combat activation therefore need measurement.
- `rate(worth, rounds)` is linear in worth for fixed capture duration/map horizon. Computing `rate(per_gold, capture_rounds) * gem_value`, then multiplying group gold, is algebraically consistent with the proposed credit. Own capture adds `gold_paid`; denial does not. Both remain a one-turn throughput hypothesis, not actual enemy value, certified progress lost, or immediate whole-camp payout. No replay-specific multiplier appears.
- Qualification is current cleared, fully visible, non-Monolith, positive gold and zero gems. It reconstructs incumbent occupancy, requires agreement with camp belief/holder, excludes every other allied body and requires an unexpired estimate for an enemy holder. Our native current position is used. Empty prospective capture and current contested occupancy are admitted. No hidden progress is multiplied. Enemy occupants remain denial until simulated death; stun alone does not remove them. Linked-pair death handling already marks both represented units; an unrepresented occupant remains conservative.
- The four new templates offer walk, plain dash, walk→plain dash and plain dash→walk only at eligible endpoints. Walk consumes the ranged basic; dash consumes the cast and existing `dash_steps * step`; nothing refunds an unperformed attack/reset or credits a damaging landing. Ordinary strike/reset/kill/heal/shield branches remain competitors. The explicit walk/dash cell fields feed the existing concrete sequence executor; a template's unchanged `seg` does not supply execution positions.
- Occupancy credit is added once per leaf endpoint. Subtracting the unused later-walk credit is appropriate because the successful economic result returns before farm/chase. The current-tile option is soft; no anchor forces it. Existing `want_home`, support work, local support, yielding, hold and bank precedence remain before it. `contesting`, Willow threat exemptions, support anchors, retreat-sideways and ally-stun semantics are untouched. The new claim is communicated through the existing end-of-turn path; the anchored wrap-up may still attack without walking off the tile.
- Successful economic commitment requires a selected economic endpoint, completed native sequence, no failure and matching actual final position. Hidden-blocker prefix fallback remains the existing executor's responsibility. The debug line is emitted before execution and is not a success record.
- Ordinary growth retains its 24-node limit; fronts retain 8 removed-enemy alternatives, 512 leaves, 49 endpoint tiles and 10 exact queries. New template offers run after ordinary growth, bounded by existing neighbors/landing cells, but can fill leaves, reorder endpoint evaluation and change which alternatives receive exact Safety pricing. Inherited nearby capped fallbacks remain possible; unchanged Safety code does not imply identical safety coverage or a guaranteed safe six-turn hold.
